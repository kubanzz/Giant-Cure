# 万物生：巨人的病历簿 · Giant Cure

面向西山居第二届游戏创意大赛试玩的原创 HTML5 生态疗愈游戏。巨人的身体是一座奇幻世界：血管是河流，毛发是森林，心脏是一座等待复苏的生命之城。

当前可玩内容为 **心脏巡诊**，以二维俯视表现诊断、分流、治疗与生命复苏。入口使用巨人生命诊断室，病例档案另展示血河淤堵、孢子侵染、心跳失序三种待开放玩法。封面、诊断室和结算保留竖版病历簿，治疗章节使用横屏插画与程序交互。

## 直接游玩

使用 Chrome 或 Edge 打开项目中的 **index.html**。该文件包含所有样式、脚本和插画，无需安装、登录、服务器或联网，单独复制它也可运行。

本章面向桌面键盘和鼠标。治疗页逻辑分辨率为 **1280×720**；封面、诊断室和结算为 **720×1280**，均随窗口等比适配。手机可进行初筛和浏览档案，章节仍需键鼠。

封面 → 患病巨人来到森林诊所 → 巨人医生听诊与扫描 → 初筛报告 → 小医疗兵进入体内 → 治疗与生命复苏。接诊自动连播：约 **4 秒**扶胸到诊、**4.5 秒**医生检查、**1.5 秒**报告揭示。人体监测图以有体积的生态巨人、肋骨、心肺与血管表现病区，显示「心区血流信号减弱」「具体病因待近距离确认」。本次初筛固定关联心脏巡诊，具体病因仍需进入身体后检查。

报告完成后等待玩家点击「进入体内治疗」。小医疗兵用约 **2 秒**检查药剂、背包并进入微缩装置，再以心区为锚点推进，经深绿遮罩、镜头到位与操作界面显现进入治疗，入体约 **1.4 秒**。完整演出共约 **13.4 秒**，报告等待和资源等待另计。插画未预载完成时停留在「正在准备治疗场景…」；载入失败可重试或返回。接诊与出发期间不推进巡诊用时、章节逻辑或关内扫描，开始游玩后从零计时。

次级「病例档案」入口可查看四项内容和真实巡诊记录。心脏巡诊可直接出诊，使用约 **250 毫秒**的淡变进入治疗；其余三项标注「待开放」，不产生诊断结果或参与治愈统计。通关后统计从 **0 / 1** 更新为 **1 / 1**，显示已治愈角标与「再次巡诊」。重复通关更新次数和最佳用时，不增加病例总数；通关记录不代表巨人当前无病或发生复发。

接诊期间禁用出发和档案入口。「跳过接诊」直接展示报告，仍由玩家点击出发。帮助、后台或失焦会冻结接诊阶段和进度，必须点击「继续接诊」恢复；Esc 或返回封面离开接诊。报告完成后打开和关闭档案保留报告，再次进入诊断室会重新接诊。减少动态效果设置使用约 **480 毫秒**的静态接诊关键帧，关闭步态、移动扫描线与循环心电；出发使用约 **200 毫秒**淡变，省略准备动作和镜头推进。

出发准备与入体期间禁用重复出发、帮助和治疗操作，保留键盘可用的「跳过出发动画」「返回封面」。跳过改走短安全淡变，资源仍须就绪。Esc、后台或失焦会取消出发并回到已完成的报告；返回封面则离开。取消清除动画、遮罩和输入，并使过期载入回调失效，避免随后创建或启动章节。

接诊状态独立于章节且不新增存档。`window.GiantCure.snapshot().clinic` 只读返回 `phase`（`idle/arriving/examining/report/ready`）、累计演出秒数 `elapsed` 与 `paused`。兼容观察字段 `diagnosis` 仍返回 `phase`（`idle/scanning/ready`）和 `caseId`：到诊、检查为 `scanning`，报告开始后为 `ready` 并关联 `heartJourney`；出发按钮仍须等待 `clinic.ready`。

`snapshot().transition` 返回 `phase` 与 `caseId`：`idle` 为空闲，`preparing` 为医疗兵准备，`departing` 为离开诊断室，`waiting` 为遮罩下等待资源，`arriving` 为治疗场景与操作界面显现。过场期间病例为 `heartJourney`，结束或取消后恢复 `null`；章节即使已创建，也须等过场结束才进入 `playing`。快照只供观察，跳过通过可见按钮操作。

## 心脏巡诊

控制戴医疗头盔、背药剂背包、持治疗器的小医疗兵，穿过血管入口、主血管与侧支、心脏内腔三个房间：

1. 对比正常支路与异常通路的流量、压力，观察统一心跳，穿过舒张时开放的瓣膜。
2. 诊断血栓，依次恢复两条侧支。每条侧支都会改变血流并降低上游压力。
3. 击败教学 Hunter 后开始治疗，立即加入三只干扰者；前两处血栓结构软化后各追加三只。边躲避、装填边完成治疗，保留当前尝试的治疗进度。
4. 双侧支恢复且血栓全部软化后启动主血流，无须清完剩余敌人；血栓碎块与剩余 Hunter 一同被带走。
5. 进入巨大心腔，扫描传导异常后出现三只 Hunter；可在干扰下连接 A→B→C，第一声强心跳净化剩余敌人、唤醒城市并解锁循环冲刺。
6. 冲刺越过屏障，扫描并暂时压制出口异常组织，亲眼看到再生；随后观看可跳过的 **8 秒**外景，巨人深呼吸、睁眼与舒展手指，树林、鸟群和村落灯火回应复苏，肺部传来下一次求救。

| 操作 | 功能 |
| --- | --- |
| WASD / Shift | 移动 / 疾行 |
| 鼠标移动 / 左键 | 决定方向 / 沿 225 单位射线持续治疗或射击 |
| 鼠标右键 | 按住精瞄、减速，预览第一命中点与目标类型 |
| Q | 开关扫描；静态诊断保留，Hunter 弱点需实时扫描 |
| E | 接近目标后交互、依次选择节点建立连接 |
| R | 装填医疗介质 |
| Space | 心脏复苏后使用循环冲刺 |
| Esc | 暂停 / 继续 |

扫描不耗能、不暂停世界。已诊断的血栓结构和出口异常组织关闭 Q 后仍可治疗，装填和躲避保留进度。射线在第一处实体停止，墙或前方 Hunter 会挡住后续目标，精瞄与实际发射共用命中结果。扩大后的组织岛与横向组织肋压缩通道，形成绕行和掩体；组织地面与浅血流槽仍可自由行走，高起组织墙和外围组织边缘阻挡通行与射击。

瓣膜闭合时安全推回进入侧，不扣耐久。第二侧支末端与瓣膜读取同一心跳的舒张窗口。常驻任务显示当前问题、选中回路和下一连接端，仅明确的下一目标提供边缘提示；临时反馈独立显示，完整操作收进帮助。血栓逐步松散剥落，三个传导节点附近的灯窗与植物随复苏依次恢复；外景演出保留暂停、声音、跳过和叙事字幕。

章节没有超时失败。遭遇预算上限为 **13 只 Hunter**：主血管预算 10、同时最多 4；心腔预算 3、同时最多 3。刷怪先有约 1 秒落点预警，避开医疗兵、节点、治疗点、门口与实体墙；没有安全位置时延后生成。每个房间同时最多两只处于扑击蓄力或扑击，敌人会绕开实体组织并分散站位，目标完成后取消待刷敌人，无须清完预算。

初始耐久 **100**；Hunter 生命值 **9**，扑击命中造成 **20** 点伤害。工具药剂匣 **24** 发、无限备药、发射间隔 **0.2 秒**、装填 **1.7 秒**，普通伤害 **1**，扫描弱点伤害 **3**。装填依次为退匣 0–0.45 秒、插入 0.45–1.25 秒、锁定 1.25–1.7 秒，配有手臂与药匣动作、进度环/条和分段音效；装填时可移动但不能发射。药剂不超过 6 发时提示低弹，空仓提供提示和一次扳机反馈。精瞄不额外降低射速。

耐久耗尽可从最近安全节点重启：**入口 → 双侧支恢复 → 主血流恢复**。重启恢复耐久和弹匣，保留已完成的大型治疗成果，重置当前阶段的敌人与未完成治疗；失败尝试的时间继续累计。退出或刷新会丢失当前检查点。

首次体验以 **3–5 分钟**为调优目标，尚待首次玩家实测。不得以熟练自动操作的用时证明首玩时长，也不通过延长治疗或强制等待凑时长。肺部仅为结尾预告，本轮不扩展其他器官、武器或敌人类型。

暂停、帮助、后台和失焦会冻结有效用时、心跳、镜头、粒子与演出，并清空持续输入。声音默认关闭，可点击音符开启；减少动态效果设置使用稳定镜头和明暗变化。浏览器通关记录继续使用 `giant-cure-journey-v1`，保留既有次数和最佳用时，不读取 `giant-cure-records-v1`。存储不可用时仍可游玩。

## 维护与构建

维护时编辑 `src/` 与 `assets/heart-journey/`，然后运行：

```sh
node scripts/bundle.js
```

三张无字房间底图、原巨人外景、森林诊所与三张复苏分层插画由内置 imagegen 制作；背景提示词记录于 `assets/heart-journey/prompts.json`。角色、诊所动作、节点、瓣膜、血栓、灯光与血流由程序绘制。构建内联八张运行时 PNG，启动时自动预载，无远程图片、字体、声音或服务依赖；音效由 Web Audio 合成。诊所插画失败时用程序背景，任一复苏图层失败时使用原巨人外景；必要房间插画失败则保留出发重试入口。

复苏制作参考 `recovery-reference.png` 保存在素材目录，不参与打包。`recoveryEyes.png` 为同构图的睁眼变体，运行时只缓存并叠加羽化眼部区域，不覆盖身体形变。外景截图与 8 秒视频预览输出到 `tests/screenshots/`，不纳入版本控制。

| 文件 | 用途 |
| --- | --- |
| `index.html` | 独立离线试玩入口 |
