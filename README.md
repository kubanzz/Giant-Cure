# 万物生：巨人的病历簿 · Giant Cure

面向西山居第二届游戏创意大赛试玩的原创 HTML5 生态疗愈游戏。巨人的身体是一座奇幻世界：血管是河流，毛发是森林，心脏是一座等待复苏的生命之城。

当前可玩内容为 **心脏巡诊**，以二维俯视表现诊断、分流、治疗与生命复苏。入口使用巨人生命诊断室，病例档案另展示血河淤堵、孢子侵染、心跳失序三种待开放玩法。封面、诊断室和结算保留竖版病历簿，治疗章节使用横屏插画与程序交互。

## 直接游玩

使用 Chrome 或 Edge 打开项目中的 **index.html**。该文件包含所有样式、脚本和插画，无需安装、登录、服务器或联网，单独复制它也可运行。

本章面向桌面键盘和鼠标。治疗页逻辑分辨率为 **1280×720**；封面、诊断室和结算为 **720×1280**，均随窗口等比适配。手机可进行初筛和浏览档案，章节仍需键鼠。

封面 → 绘本巨人接受诊断 → 心区初筛报告 → 医疗兵乘透明胶囊沿导管进入心区 → 心脏巡诊与生命复苏。封面、接诊与通关结尾共用同一位卧躺巨人：米白纸底、灰绿块面、少量树木和村落，暖金心区是唯一诊断重点。小医疗兵与房屋提供巨人尺度参照，不再出现双巨人听诊、写实胸口插画、全身器官线网或独立微缩装置页面。接诊自动连播约 **3 秒**：**0.6 秒**显现患者、**1.8 秒**柔和波纹检查、**0.6 秒**揭示报告。报告为「心区血流信号减弱」「具体病因待近距离确认」，具体病因留给体内检查。

报告完成后等待玩家点击「将医疗兵送入心区」。医疗兵用 **0.5 秒**进入透明微缩胶囊，再用 **0.9 秒**沿胸口短导管抵达心区；随后 **0.3 秒**从同一心区推进、**0.3 秒**显现治疗场景。出发与入体共约 **2 秒**，完整演出约 **5 秒**，报告停留和资源等待另计。医疗兵头盔、白绿制服和背包在装舱时仍可辨认，胶囊到达心区后才切换场景。必要房间底图尚未预载完成时停留在「正在准备治疗场景…」；载入失败可重试或返回。接诊与出发期间不推进巡诊用时、章节逻辑或关内扫描，开始游玩后从零计时。

次级「病例档案」入口可查看四项内容和真实巡诊记录。心脏巡诊可直接出诊，使用约 **250 毫秒**的淡变进入治疗；其余三项标注「待开放」，不产生诊断结果或参与治愈统计。通关后统计从 **0 / 1** 更新为 **1 / 1**，显示已治愈角标与「再次巡诊」。重复通关更新次数和最佳用时，不增加病例总数；通关记录不代表巨人当前无病或发生复发。

接诊期间禁用出发和档案入口。「跳过接诊」直接展示报告，仍由玩家点击出发。帮助、后台或失焦冻结接诊阶段和进度，必须点击「继续接诊」恢复；Esc 或返回封面离开接诊。报告完成后打开和关闭档案保留报告，再次进入诊断室重新接诊。减少动态效果使用约 **480 毫秒**静态诊断关键帧，关闭循环波纹与植物摆动；出发显示胶囊已抵达心区的静态提示，再使用约 **200 毫秒**淡变，省略投送移动和镜头推进。

出发准备与入体期间禁用重复出发、帮助和治疗操作，保留键盘可用的「跳过出发动画」「返回封面」。跳过改走短安全淡变，资源仍须就绪。Esc、后台或失焦会取消出发并回到已完成的报告；返回封面则离开。取消清除动画、遮罩和输入，并使过期载入回调失效，避免随后创建或启动章节。

接诊状态独立于章节且不新增存档。`window.GiantCure.snapshot().clinic` 只读返回 `phase`（`idle/arriving/examining/report/ready`）、累计演出秒数 `elapsed` 与 `paused`。兼容观察字段 `diagnosis` 仍返回 `phase`（`idle/scanning/ready`）和 `caseId`：到诊、检查为 `scanning`，报告开始后为 `ready` 并关联 `heartJourney`；出发按钮仍须等待 `clinic.ready`。

巨人、诊断与胶囊投送使用同一构图和同一心区坐标。`GiantCureGiantArt.draw/getFrame(options)` 接受目标画幅、有效演出时间、恢复进度与减少动态标记，向封面、接诊和结尾返回一致的心区投影。`GiantCureClinicArt.getFrame(clinic, time, images)` 兼容保留 `heart/scanProgress/shot/camera`，`draw()` 返回同一份元数据。出发时复制接诊 Canvas 当前像素到过场克隆，再在该画布内绘制医疗兵装舱和导管投送；不再切到独立准备页。窗口缩放后导管终点、胶囊落点和镜头仍对齐同一个心区。

`snapshot().transition` 返回 `phase` 与 `caseId`：`idle` 为空闲，`preparing` 为医疗兵准备，`departing` 为离开诊断室，`waiting` 为遮罩下等待资源，`arriving` 为治疗场景与操作界面显现。过场期间病例为 `heartJourney`，结束或取消后恢复 `null`；章节即使已创建，也须等过场结束才进入 `playing`。快照只供观察，跳过通过可见按钮操作。

## 心脏巡诊

控制戴医疗头盔、背药剂背包、持治疗器的小医疗兵，穿过血管入口、主血管与侧支、心脏内腔三个房间：

1. 对比正常支路与异常通路的流量、压力，观察统一心跳，穿过舒张时开放的瓣膜。
2. 用精准治疗枪疏通任意一条侧支：左路有掩体、处理较慢，右路更暴露、处理较快。血细胞真正改道，压力下降，外部注射的补给囊沿恢复路线运来裂解喷头，靠近按 E 领取。
3. 切换裂解喷头处理两处纤维外层，核心暴露后改用精准枪治疗；墙体与前方敌人会挡住工具。可以先清敌或借掩护抢治疗，无须先击败教学敌人。
4. 任一侧支与血栓治疗完成后启动主流，冲走血栓和余敌，不要求清完遭遇预算。
5. 进入心腔复测，发现血流恢复但脉冲仍在某处中断。比较三个被动采样位置，定位有输入、无输出的故障，接收第二次补给并用脉冲探针修复。三次脉冲真实抵达下游后确认同步，强心跳净化余敌、复苏城市并解锁冲刺。
6. 冲刺越过屏障，扫描并暂时压制出口异常组织，亲眼看到再生；随后观看可跳过的 **8 秒**外景，同一绘本巨人深呼吸、心区恢复平稳跳动，树林和村落灯火回应复苏，肺部传来下一次求救。

| 操作 | 功能 |
| --- | --- |
| WASD / Shift | 移动 / 疾行 |
| 鼠标移动 / 左键 | 决定方向 / 持续使用当前工具 |
| 鼠标右键 | 按住精瞄、减速，预览第一命中点与目标类型 |
| Q | 观察病情和扫描进度；Hunter 仅恢复期暴露弱点 |
| 1 / 2 / 3 | 精准治疗枪 / 裂解喷头 / 脉冲探针，也可点击工具栏 |
| E | 领取外部补给、打开可选医疗箱、操作主流阀或过门 |
| R | 提前装填；空匣会自动装填 |
| Space | 心脏复苏后使用循环冲刺 |
| Esc | 暂停 / 继续 |

扫描免费、不暂停世界，显示读取进度和输入/输出差异。知道病灶位置后可直接治疗，不以扫描标记作命中门禁。精准枪/探针射程 225；喷头为 145 射程、60°扇形，可命中多个无遮挡敌人。墙体和前方实体会挡住治疗，预览与实际作用共用求交结果。局部病灶进度在躲避、装填和暂停中保留。

瓣膜闭合时安全推回进入侧，不扣耐久。侧支和传导不再要求 ABC 顺序操作；常驻任务按所在房间、病情与工具持有给出下一步。纤维剥落、核心暴露、脉冲经过故障和下游接收由实际治疗状态驱动，三拍复测并入原有复苏。外景保留暂停、声音、跳过和叙事字幕。

章节没有超时失败。遭遇预算上限为 **13 只 Hunter**：主血管预算 10、同时最多 4；心腔预算 3、同时最多 3。刷怪先有约 1 秒落点预警，避开医疗兵、节点、治疗点、门口与实体墙；没有安全位置时延后生成。每个房间同时最多两只处于扑击蓄力或扑击，敌人会绕开实体组织并分散站位，目标完成后取消待刷敌人，无须清完预算。

初始耐久 **100**；Hunter 生命值 **9**、扑击伤害 **20**、普通命中 **1**、恢复期扫描弱点命中 **3**。三工具共用 **24** 发介质匣、无限备料、**0.2 秒**发射间隔。最后一发有效治疗量结清后自动开始 **1.7 秒**三段装填；可以移动，按住左键可在装填后继续，暂停或松手后不误续射。探针只修复传导故障，不伤害敌人。

入口正常支路附近有一个可选医疗箱，打开后暂停并二选一：缓冲凝胶提供一次 **20** 点护层、检查点重启恢复；稳流药匣将装填缩短为 **1.2 秒**。装备自动生效、不能重复领取或重选，无箱也可完整通关。两次必得工具补给不会被敌人毁掉，允许折返领取。

耐久耗尽可从最近安全节点重启：**入口 → 任一侧支恢复 → 主血流恢复**。重启恢复耐久、弹匣和凝胶护层，保留完整病灶成果、工具、装备与补给；未完成治疗回退。存活敌人保留伤势并安全重定位，触发和预算不重复。失败时间继续累计，退出或刷新清除本次检查点和装备。

首次体验以 **6–8 分钟**为调优目标，仍待真人实测。自动路线用时不能证明首玩时长，不靠堆敌人血量、延长照射或强制等待凑时长。肺部仅为预告；本轮装备只服务本关，不增加其他器官、随机配装或敌人类型。

暂停、帮助、后台和失焦冻结用时、心跳、镜头、粒子和演出，并清空持续输入。声音默认关闭；减少动态效果使用稳定镜头和明暗变化。新版记录使用 `giant-cure-journey-v2`，首次从 V1 迁移通关次数，但不继承旧规则最佳用时；已有 V2 优先，旧数据不改写。存储不可用仍可游玩。

## 维护与构建

维护时编辑 `src/` 与 `assets/heart-journey/`，然后运行：

```sh
node scripts/bundle.js
```

运行时仅内联 **3 张 PNG**：`entry/main/heart` 三张无字房间底图，来源与提示词记录于 `assets/heart-journey/prompts.json`。封面、接诊和结尾的卧躺巨人由共享程序组件绘制，医疗兵、胶囊、导管、诊断波纹、呼吸、心跳与村落灯光也由程序绘制；本轮不生成新图片。所有样式、脚本和房间底图仍包含在单文件入口，无远程图片、字体、声音或服务依赖；音效由 Web Audio 合成。

原七张 `clinic*` 接诊图、`exterior` 完整外景图及 `recoveryValley/recoveryGiant/recoveryEyes` 三张复苏图层均已退出运行时打包、预载与回退流程，制作源文件和提示词仍保留。`GiantCureAssets.images` 仅含三个房间键；`clinicError/recoveryError` 作为兼容观察字段保留为 `null`。必要房间插画失败仍提供出发重试入口。

原 `clinic.png`、`recovery-reference.png`、`creatureRecovery-reference.png` 及相关接诊、外景、复苏图层仅作制作历史，不参与打包。结尾保留 **8 秒**，同一绘本患者依次表现深呼吸、心区恢复稳定跳动、林梢轻动与村落亮灯，最后提示肺部求救。减少动态效果使用稳定构图和轻微明暗变化。外景截图输出到 `tests/screenshots/`，不纳入版本控制。
