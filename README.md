# 万物生：巨人的病历簿 · Giant Cure

面向西山居第二届游戏创意大赛试玩的原创 HTML5 生态疗愈游戏。巨人的身体是一座奇幻世界：血管是河流，毛发是森林，心脏是一座等待复苏的生命之城。

当前可玩内容为 **心脏巡诊**，以二维俯视表现诊断、分流、治疗与生命复苏。入口使用横版巨人扫描室，病例档案另展示血河淤堵、孢子侵染、心跳失序三种待开放玩法。封面和结算保留竖版病历簿，扫描、定位与治疗章节使用横屏插画与程序交互。

## 直接游玩

使用 Chrome 或 Edge 打开项目中的 **index.html**。该文件包含所有样式、脚本和插画，无需安装、登录、服务器或联网，单独复制它也可运行。

本章面向桌面键盘和鼠标。扫描与治疗页逻辑分辨率为 **1280×720**；封面和结算为 **720×1280**，均随窗口等比适配。手机竖屏提示横屏体验，仍可点击初筛、确认和档案控件，章节仍需键鼠。

封面 → **01 扫描巨人 → 02 确认异常部位 → 03 进入诊断** → 心脏巡诊与生命复苏。扫描室使用暖纸水彩的完整卧躺森林巨人，程序叠加半透明器官、绿色扫描带、医疗兵和心区准星。插画就绪后自动连播约 **3 秒**：**0.6 秒**显现患者、**1.8 秒**扫描检查、**0.6 秒**揭示报告；百分比与实际扫描进度一致，无需 WASD 或 Q。定位后显示心区报告和血管放大镜，具体病因留给体内检查。封面与通关结尾继续使用原共享绘本组件。

报告完成后等待玩家点击「确认并进入诊断」。医疗兵用 **0.5 秒**进入透明微缩胶囊，再用 **0.9 秒**沿胸口短导管抵达心区；随后 **0.3 秒**从同一心区推进、**0.3 秒**显现治疗场景。出发与入体共约 **2 秒**，完整演出约 **5 秒**，报告停留和资源等待另计。必要房间底图尚未预载完成时停留在「正在准备治疗场景…」；载入失败可重试或返回。接诊与出发期间不推进巡诊用时、章节逻辑或关内扫描，开始游玩后从零计时。体内开场显示第三阶段标题、身体心区小图和真实入口凝块的待扫描提示，沿用 Q 近距离诊断；确认首次诊断单或直接治好凝块后恢复常规治疗 HUD。

次级「病例档案」入口可查看四项内容和真实巡诊记录。心脏巡诊可直接出诊，使用约 **250 毫秒**的淡变进入治疗；其余三项标注「待开放」，不产生诊断结果或参与治愈统计。通关后统计从 **0 / 1** 更新为 **1 / 1**，显示已治愈角标与「再次巡诊」。重复通关更新次数和最佳用时，不增加病例总数；通关记录不代表巨人当前无病或发生复发。

接诊期间禁用出发和档案入口。「跳过接诊」直接展示报告，仍由玩家点击出发。顶部暂停、帮助、后台或失焦冻结接诊阶段和进度，点击继续后恢复；Esc 或返回封面离开接诊。报告完成后打开和关闭档案保留报告，再次进入诊断室重新接诊。减少动态效果使用约 **480 毫秒**静态诊断关键帧，关闭扫描带移动；出发显示胶囊已抵达心区的静态提示，再使用约 **200 毫秒**淡变，省略投送移动和镜头推进。

出发准备与入体期间禁用重复出发、帮助和治疗操作，保留键盘可用的「跳过出发动画」「返回封面」。跳过改走短安全淡变，资源仍须就绪。Esc、后台或失焦会取消出发并回到已完成的报告；返回封面则离开。取消清除动画、遮罩和输入，并使过期载入回调失效，避免随后创建或启动章节。

接诊状态独立于章节且不新增存档。`window.GiantCure.snapshot().clinic` 只读返回 `phase`（`idle/arriving/examining/report/ready`）、累计演出秒数 `elapsed` 与 `paused`。兼容观察字段 `diagnosis` 仍返回 `phase`（`idle/scanning/ready`）和 `caseId`：到诊、检查为 `scanning`，报告开始后为 `ready` 并关联 `heartJourney`；出发按钮仍须等待 `clinic.ready`。

扫描、定位与胶囊投送使用同一构图和同一心区坐标。`GiantCureClinicArt.getFrame(clinic, time, images)` 兼容保留 `heart/scanProgress/shot/camera`，新增 `scene.width/height` 描述 **1232×552** 场景，`draw()` 返回同一份元数据。出发时复制接诊 Canvas 当前像素到过场克隆，再在该画布内绘制医疗兵装舱和导管投送。窗口缩放后导管终点、胶囊落点和镜头仍对齐同一个心区。`GiantCureGiantArt` 继续负责封面与结尾。

`snapshot().transition` 返回 `phase` 与 `caseId`：`idle` 为空闲，`preparing` 为医疗兵准备，`departing` 为离开诊断室，`waiting` 为遮罩下等待资源，`arriving` 为治疗场景与操作界面显现。过场期间病例为 `heartJourney`，结束或取消后恢复 `null`；章节即使已创建，也须等过场结束才进入 `playing`。快照只供观察，跳过通过可见按钮操作。

## 心脏巡诊 · V4

本章围绕“扫描诊断单 → 针对治疗 → 关闭威胁来源 → 主动复测”展开，入口、主血管、心腔逐步扩大为 **2000×1250 / 2200×1400 / 2600×1700**。首次体验 **6–8 分钟**仍是调优目标，实际理解、趣味性和成就感待真人盲测。

1. 入口先观察正常与异常血流，用精准枪清除东侧轻度凝块，看到局部组织与血流恢复；更深处高压仍在，引向主血管。通行检查实际救治成果，扫描不再充当开门按钮。
2. 主血管任选一条侧支疏通。治疗开始后，凝集体从血栓中持续产生，冲撞医疗兵或组织；两处维护点受到破坏会漏流、降低灌流，必须抢修。外部补给沿恢复侧支运来裂解喷头，领取不会自动换枪。
3. 用喷头裂解两处纤维，再用精准枪处理暴露核心。纤维织体会远程投放覆盖物并损伤组织：1 精准枪可直接修补覆盖下的裂口，2 喷头可单独清理覆盖物。根治主病灶且心脏稳定度至少 60 后，按 E 启动主流，关闭增援并冲走余敌。
4. 心腔分为两区，可选择先后顺序：西区先用 2 裂解纤维、东区先用 1 疏通凝块，再分别用 3 接通传导。每区修好即关闭本区来源、清除其威胁并建立检查点；双区恢复且稳定度至少 60 后进入同步验证。
5. 使用 3 分三次点击同步核心，每次实际脉冲抵达下游才计一拍；长按只发一次。验证阶段可以移动、扫描和选枪，三拍通过才开放出口。
6. 到出口按 E 撤离，观看可跳过的 **8 秒**绘本巨人复苏，再收到肺部求救。结算展示 S/A/B 评级及组织守护、精准医师、稳健巡诊三枚徽章，鼓励保护组织、命中弱点和减少重试。

| 操作 | 功能 |
| --- | --- |
| WASD / Shift | 移动 / 疾行 |
| 鼠标移动 / 左键 | 瞄准 / 持续治疗或射击 |
| 鼠标右键 | 精瞄、减速并预览真实首个命中点 |
| Q / J | 开关单目标扫描 / 回看当前诊断单 |
| 1 / 2 / 3 | 精准治疗枪 / 纤维裂解喷头 / 导电脉冲探针 |
| 按住 Tab | 暂停世界并展开选枪面板；鼠标、左右键或数字键选候选，松开确认 |
| E / R | 领取补给、操作主流或房门 / 提前装填 |
| Space | 从开场可用的基础冲刺，持续 0.34 秒、速度 450、冷却 2.4 秒 |
| Esc | 暂停；选枪时取消候选并打开普通暂停 |

三枪共用 **24** 发介质匣、无限备料、**0.2 秒**发射间隔；三段装填缩短一半至 **0.85 秒**。精准枪修补组织每秒 20，喷头清除附着需 0.8 秒有效作用，探针接通两区并主动验证。射线、预览、治疗和伤害共用遮挡判断。

Q 扫描优先锁定鼠标指向的范围内对象，之后按距离选择，一次只读一个对象。入口检测与凝块合并、主血栓与三处弱点合并，读取完成自动关闭扫描。首次关键诊断或关键状态变化会弹出简洁诊断单，列出结果与明确操作，**阅读时冻结全局、装填和计时**。同状态重复扫描仅短反馈，J 或按钮可主动回看实时结果；Esc 进入普通暂停，失焦保留报告。关闭扫描仍可治疗已知病灶。

三图统一移除装饰与非关键物品描述，组织旁只保留焦点短名、交互键、进度和短失败原因。原顶部累积诊断长文改为当前扫描状态，病情与工具解释集中在诊断单。

**心脏稳定度**与医疗兵 **100** 耐久分开显示。每战斗区两处维护点，各 **50** 完整度，当前未修复损伤共同影响稳定度；单次组织攻击扣 10。单点归零仍可修复，共享稳定度归零或医疗兵耐久归零才失败。主血管病灶完成且稳定度至少 **60** 才能启动冲流，冲流清除余敌并恢复组织。心腔每区接通后关闭本区来源、保护对应组织，已有损伤仍需用 1 修补；双区完成且稳定度至少 60 才能复测。防守期间回程暂锁，复测通过后重新开放。

每区首批两只，此后每 **8 秒**尝试补充一只；同时上限为主血管 **4**、心腔 **4**，同时最多两只发动攻击。刷怪有约 1 秒预警，避开玩家、治疗点、补给、门口与实体墙。心腔敌人与各自来源和组织关联，完成一区可永久改变本次战况，无需反复清完敌人。

耐久或稳定度归零后，可从 **入口 → 任一侧支恢复 → 主血流恢复 → 任一心腔区传导恢复**的安全节点重试。保留完整治疗成果、已获工具和补给；恢复玩家、弹匣及组织，清除当前区敌人和预警，给予 3 秒准备期。未完成病灶治疗回退，已完成心腔区保留；重试后重新进行主动三拍。失败用时继续累计，退出或刷新清除本次检查点。

Tab 选枪、暂停、帮助、失焦和后台冻结计时、装填、心跳、敌人、器官稳定度和画面演出。选枪失焦会取消候选并保持暂停，松开 Tab 不会误恢复。恢复后不会继承持续射击。声音默认关闭，减少动态效果使用稳定镜头与明暗反馈。

记录使用 `giant-cure-journey-v4`，保存次数、最佳时间、最佳评级及累计徽章。已有 V4 优先，否则依次从 V3 / V2 / V1 迁移通关次数，清除旧规则最佳用时与评级，旧数据不改写。组织守护要求全程稳定度至少 60，精准医师要求命中三个不同凝集体的暴露弱点，稳健巡诊要求零重试；三枚为 S、两枚为 A，其余为 B。存储不可用仍可游玩，`heartStable` 只在修复与真实三拍复测后成立。

## 维护与构建

维护时编辑 `src/` 与 `assets/heart-journey/`，然后运行：

```sh
node scripts/bundle.js
```

运行时内联 **4 张 PNG**：`entry/main/heart` 三张无字房间底图及扫描底图 `scanGiant`。当前扫描底图经用户确认使用 Canvas 手绘，按参考图的圆润简笔人物、叶裙与浅色平涂重做；绘制来源见 `assets/heart-journey/scanGiant-art.json`。原 AI 绘画提示词在 `scanGiant-prompts.json` 中保留为已被替换的历史记录。半透明器官与扫描效果仍由运行时独立程序绘制。所有样式、脚本和插画均包含在单文件入口，无远程图片、字体、声音或服务依赖；音效由 Web Audio 合成。

重新绘制扫描底图可运行 `node scripts/render-scan-giant.cjs`，再执行打包命令。绘制源文件为该脚本及 `scripts/scan-giant-foliage.cjs`，作者工具需要 `@napi-rs/canvas`；试玩入口无需这个依赖。

原七张 `clinic*` 接诊图、`exterior` 完整外景图及 `recoveryValley/recoveryGiant/recoveryEyes` 三张复苏图层仍只保留制作源文件。`GiantCureAssets.ready/retry()` 管理三个治疗房间；`clinicReady/retryClinic()` 单独管理扫描图，失败由 `clinicError` 返回，并提供重新载入或返回封面。扫描与治疗资源的错误和重试互相独立；`recoveryError` 仍为 `null`。

原 `clinic.png`、`recovery-reference.png`、`creatureRecovery-reference.png` 及相关接诊、外景、复苏图层仅作制作历史，不参与打包。结尾保留 **8 秒**，同一绘本患者依次表现深呼吸、心区恢复稳定跳动、林梢轻动与村落亮灯，最后提示肺部求救。减少动态效果使用稳定构图和轻微明暗变化。外景截图输出到 `tests/screenshots/`，不纳入版本控制。
