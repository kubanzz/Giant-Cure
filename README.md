# 万物生：巨人的病历簿 · Giant Cure

面向西山居第二届游戏创意大赛试玩的原创 HTML5 生态疗愈游戏。巨人的身体是一座奇幻世界：血管是河流，毛发是森林，心脏是一座等待复苏的生命之城。

当前可玩内容为 **心脏巡诊**，以二维俯视表现诊断、分流、治疗与生命复苏。入口使用巨人生命诊断室，病例档案另展示血河淤堵、孢子侵染、心跳失序三种待开放玩法。封面、诊断室和结算保留竖版病历簿，治疗章节使用横屏插画与程序交互。

## 直接游玩

使用 Chrome 或 Edge 打开项目中的 **index.html**。该文件包含所有样式、脚本和插画，无需安装、登录、服务器或联网，单独复制它也可运行。

本章面向桌面键盘和鼠标。治疗页逻辑分辨率为 **1280×720**；封面、诊断室和结算为 **720×1280**，均随窗口等比适配。手机可进行初筛和浏览档案，章节仍需键鼠。

封面 → 进入诊断室 → 开始检查 → 异常已定位 → 前往治疗 → 查看结果。初筛约 **2.8 秒**，扫描线掠过身体轮廓后定位心区，显示「心区血流信号减弱」「具体病因待近距离确认」。本次初筛固定关联心脏巡诊，不随机选择疾病；具体病因仍需进入身体后检查。

点击「前往治疗」后，以心区为锚点推进，经过深绿遮罩进入治疗场景，镜头落到医疗单位后再显现操作界面；正常过场约 **1.4 秒**。插画若尚未预载完成，会停留在「正在准备治疗场景…」，等待时间另计；载入失败提供重试和返回。过场结束前不接受玩法输入，也不推进巡诊用时和章节逻辑，结束后从零开始计时。

次级「病例档案」入口可查看四项内容和真实巡诊记录。心脏巡诊可直接出诊，使用约 **250 毫秒**的淡变进入治疗；其余三项标注「待开放」，不产生诊断结果或参与治愈统计。通关后统计从 **0 / 1** 更新为 **1 / 1**，显示已治愈角标与「再次巡诊」。重复通关更新次数和最佳用时，不增加病例总数；通关记录不代表巨人当前无病或发生复发。

检查中禁用重复检查和档案入口；离开诊断室、打开帮助、切到后台或窗口失焦会取消未完成检查。诊断完成后不提供重抽，打开和关闭档案保留初筛结果，离开后再次进入则恢复待检查。减少动态效果设置下，初筛使用 **160 毫秒淡入**，关闭移动扫描线和循环波形；出诊过场统一使用约 **200 毫秒淡变**，跳过缩放推进。

出诊过场期间禁用重复出诊、帮助和治疗操作，保留可用键盘聚焦的「返回封面」。按 Esc、切到后台或窗口失焦会取消过场并回到诊断室，保留原先已完成的初筛结果；点击「返回封面」则退出到封面。取消会清除动画、临时遮罩和输入，并使过期载入回调失效，避免随后创建或启动章节。

初筛状态独立于章节，不创建游戏实例、不推进章节计时、不填充关内扫描记录，也不新增存档。`window.GiantCure.snapshot().diagnosis` 只读返回 `phase`（`idle` / `scanning` / `ready`）和已定位的 `caseId`；只有 `ready` 时关联 `heartJourney`，替代旧入口的 `selector` 诊断。

`window.GiantCure.snapshot().transition` 只读返回 `phase` 和 `caseId`：`idle` 表示无出诊过场，`departing` 表示离开诊断室，`waiting` 表示遮罩下等待场景资源，`arriving` 表示治疗场景与操作界面正在显现。过场期间 `caseId` 为 `heartJourney`，结束或取消后恢复 `null`；章节即使已创建，也要等过场结束才进入 `playing` 并接受玩法输入。这两个快照仅供观察，不提供修改状态或跳过过场的接口。

## 心脏巡诊

控制微小的医疗单位，穿过血管入口、主血管与侧支、心脏内腔三个房间：

1. 对比正常支路与异常通路的流量、压力，观察统一心跳，穿过舒张时开放的瓣膜。
2. 诊断血栓，依次恢复两条侧支。每条侧支都会改变血流并降低上游压力。
3. 处理首只 Hunter 后开始软化三处血栓结构；后续两只 Hunter 与治疗同时进行，躲避时保留当前尝试的治疗进度。
4. 双侧支恢复且血栓全部软化后启动主血流，无须清完剩余敌人；血栓碎块与剩余 Hunter 一同被带走。
5. 进入巨大心腔，扫描传导异常并连接 A→B→C，唤醒城市、恢复心跳并解锁循环冲刺。
6. 冲刺越过屏障，扫描并暂时压制出口异常组织，亲眼看到再生；巨人胸口恢复搏动，肺部传来下一次求救。

| 操作 | 功能 |
| --- | --- |
| WASD / Shift | 移动 / 疾行 |
| 鼠标移动 / 左键 | 瞄准 / 持续治疗或射击 |
| 鼠标右键 | 按住精瞄，降低移动速度并显示辅助射线 |
| Q | 开关扫描，读取附近组织症状和异常细胞弱点 |
| E | 接近目标后交互、依次选择节点建立连接 |
| R | 装填医疗介质 |
| Space | 心脏复苏后使用循环冲刺 |
| Esc | 暂停 / 继续 |

扫描不耗能、不暂停世界。实体组织会阻挡射击；瓣膜闭合时安全推回进入侧，不扣耐久。第二侧支末端与瓣膜读取同一心跳的舒张窗口。常驻目标描述当前问题，临时反馈单独显示；帮助按当前阶段提供线索。

章节没有超时失败。初始耐久 **100**；Hunter 有扑击预警，命中造成 **20** 点伤害。医疗工具弹匣 **24** 发、无限备弹、装填 **1.7 秒**；Hunter 生命值 **6**，普通伤害 **1**，扫描弱点伤害 **3**。精瞄不额外降低射速。

耐久耗尽可从最近安全节点重启：**入口 → 双侧支恢复 → 主血流恢复**。重启恢复耐久和弹匣，保留已完成的大型治疗成果，重置当前阶段的敌人与未完成治疗；失败尝试的时间继续累计。退出或刷新会丢失当前检查点。

首次体验以 **3–5 分钟**为调优目标，尚待首次玩家实测。不得以熟练自动操作的用时证明首玩时长，也不通过延长治疗或强制等待凑时长。肺部仅为结尾预告，本轮不扩展其他器官、武器或敌人类型。

暂停、帮助、后台和失焦会冻结有效用时、心跳、镜头、粒子与演出，并清空持续输入。声音默认关闭，可点击音符开启；减少动态效果设置使用稳定镜头和明暗变化。浏览器通关记录继续使用 `giant-cure-journey-v1`，保留既有次数和最佳用时，不读取 `giant-cure-records-v1`。存储不可用时仍可游玩。

## 维护与构建

维护时编辑 `src/` 与 `assets/heart-journey/`，然后运行：

```sh
node scripts/bundle.js
```

三张无字场景底图与巨人外景由内置 imagegen 制作；角色、节点、瓣膜、血栓、灯光和血流由程序绘制。构建将四张本地 PNG 内联到 HTML，启动时自动预载，无远程图片、字体、声音或服务依赖。音效由 Web Audio 合成。

| 文件 | 用途 |
| --- | --- |
| `index.html` | 独立离线试玩入口 |
| `src/index.template.html` / `src/styles.css` | 病历簿、横屏治疗布局和 HUD |
| `src/app.js` | 导航、相机、指针换算、计时、暂停、音效、结算与存储 |
| `src/cover.js` | 生态巨人封面 |
| `src/heart-journey.js` | 章节状态、世界几何、诊断、碰撞、战斗和检查点 |
| `src/journey-art.js` / `src/journey-assets.js` | 世界绘制、插画载入与恢复演出 |
| `assets/heart-journey/` | 三个房间底图与巨人外景源文件 |
| `tests/` | 控制器与真实浏览器输入回归 |

当前二维版本的规则、接口与验收见 [章节实现说明](Docs/HeartJourney.md) 和 [5 人盲测记录](Docs/HeartJourneyPlaytest.md)。`Docs` 中另外七份文档保留原 3D / UE 方案的参考性质，不作为本网页版本已完成或通过验收的依据。

## 验证

```sh
node tests/journey-controllers.cjs
node tests/browser.cjs
node tests/journey-browser.cjs
```

```sh

npx playwright install chromium
```
