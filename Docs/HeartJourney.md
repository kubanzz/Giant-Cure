# 心脏巡诊：二维横屏章节实现说明

本章 V2 以“观察症状 → 定位病因 → 接收针对补给 → 在威胁下治疗 → 复测身体反应”构成二维俯视体验。诊断与战斗均衡，首玩目标为 **6–8 分钟**；目标时长和体验效果尚待真人验证，不以自动操作时长代替。

本轮保留三个房间、三个检查点、有限 Hunter 遭遇与首尾演出，加入两次必得补给、三种针对工具和一个可选装备箱，装备只在本次巡诊内使用。取消侧支和传导 ABC 连接门禁；肺部只作结尾预告，不扩展其他器官、敌人类型或 UE 系统。本目录七份原始 3D / UE 规划保留为参考，本文件定义网页版本的实现口径。

## 接诊与出发

封面、竖版接诊与通关结尾复用同一位卧躺绘本巨人：米白纸底、灰绿块面和暖金心区，保留少量树木、房屋以及身旁小医疗兵的尺度参照。自动诊断共 **3 秒**：0.6 秒显现患者，1.8 秒用柔和波纹检查胸口，0.6 秒亮起心区并揭示初筛报告。没有第二位巨人医生、写实听诊插画或独立微缩装置页。

诊断保持完整患者构图，暖金心区为唯一重点，不显示全身器官线网或十字准星。报告定位「心区血流信号减弱」「具体病因待近距离确认」，具体病因留给体内检查。小医疗兵保留医疗头盔、白绿制服和背包，装入透明胶囊时仍可辨认。

报告完成后等待玩家点击「将医疗兵送入心区」。出发共约 **2 秒**：0.5 秒医疗兵进入透明胶囊，0.9 秒胶囊沿可见短导管抵达胸口心区，0.3 秒从同一心区推进，0.3 秒显现关卡。完整演出约 **5 秒**，报告停留和资源等待另计。胶囊抵达后才能进入推进；接诊不创建关卡或填写关内扫描，出发即使已创建关卡也冻结玩法，直到 `playing` 才开始接受输入和累计用时。

- 「跳过接诊」直接完成报告，保持显式出发；「跳过出发动画」改走约 200 毫秒安全淡变，仍须等待资源，不能提前进入玩法。
- 接诊演出中的帮助、后台与失焦冻结当前阶段和累计进度，必须通过「继续接诊」恢复；Esc 或返回封面离开。仅关闭帮助弹窗（如按 Esc）不会恢复接诊，点击其「继续接诊」按钮才恢复。
- 出发准备、推进、资源等待、镜头显现期间，Esc、后台或失焦取消并返回已完成的报告；返回封面则离开。token 使过期动画与资源回调失效，清空持续输入并恢复焦点。
- 减少动态效果下使用约 480 毫秒静态接诊关键帧，关闭循环波纹和树木摆动；出发保留胶囊已抵达心区的静态提示，省略投送移动与镜头推进，使用约 200 毫秒淡变。再次进入诊断室重新接诊，档案开关保留报告。

## 章节与规则

| 状态 | 玩家行为与推进条件 |
| --- | --- |
| `diagnosis` | 对比入口正常支路与异常通路的流量、压力；扫描异常压力后可进入主血管，继续诊断血栓。正常支路扫描可选且可折返。 |
| `bypass` | 用精准治疗枪疏通任一侧支。左路有组织掩体，需要 4 秒有效治疗；右路更暴露，需要 2.4 秒。首条贯通即降压并建立检查点。 |
| `supply` | 外部裂解补给沿已恢复侧支运输约 3 秒，落在可达安全点，靠近按 E 原子领取裂解喷头。补给不会被敌人破坏，允许折返。 |
| `clot` | 裂解喷头处理两个不同朝向的纤维区域，各 2.4 秒，之后精准治疗暴露核心 3.2 秒。不必先杀教学敌人，可以先清敌或抢治疗。 |
| `burst` | 任一侧支与全部血栓结构完成后启动主流阀。约 4 秒冲流带走血栓和余敌，建立主血流检查点。 |
| `conduction` | 首次心腔揭示约 1.5 秒；三处采样点只被动显示输入/输出。脉冲停在实际故障，扫描中央信号或故障后收到探针补给；用探针修复故障 2.4 秒。 |
| `recovery` | 关闭心腔队列，强心跳净化余敌。统一心跳生成的脉冲真实抵达末端才计为一次复测；三次抵达合入约 6 秒复苏，达标后解锁冲刺。 |
| `escape` | 循环冲刺越过出口屏障；扫描异常组织，持续治疗约 1.5 秒将其暂时压制。 |
| `ending` / `complete` | 总计 11.8 秒：0–1.8 秒暂时压制、1.8–3.8 秒再生、3.8–11.8 秒为可跳过的 8 秒巨人外景复苏，结束只结算一次。 |

扫描不耗能、不暂停世界。普通目标范围 145，血栓总诊断范围 230，累计 1.35 秒；目标显示扫描进度、范围不足和已保存状态。观察决定处理位置与工具；知道病灶位置后可以直接治疗，不以扫描标记作为命中门禁。主流释放仍检查实际分流与治疗成果。

入口瓣膜读取统一心跳，闭合时安全推回进入侧，不扣耐久，不加入血流推力。两条侧支不再读取连接顺序或舒张窗口；第一条贯通即实际分流。左侧小掩体阻挡移动与射线；右侧保持暴露。下游血流、压力、补给运输和病灶外观由同一控制器状态驱动。

工具为 `precision/sprayer/probe`，按 1/2/3、小键盘或工具栏切换；未领取工具不能使用。精准枪射程 225，处理侧支、暴露核心与出口异常；喷头射程 145、夹角 60°，处理纤维并对多个无遮挡 Hunter 造成普通伤害；探针射程 225，只处理传导故障，不对敌人造成伤害。错误工具有明确反馈，健康组织不改善读数。切换工具与领取补给清除持续开火，不误继承扳机。

暂停照射、装填、躲避、暂停或失焦保留当前治疗量。重试保留完整治好的局部目标，未完成目标回退至零；诊断记录、已获工具、装备、补给领取与敌人触发状态保留。战斗不锁回程门，折返不补资源。

遭遇预算仍为主血管 10、心腔 3，同时上限 4/3。主血管初入排队 1 只、领取喷头 3 只、每层纤维完成各 3 只；心腔进入后触发，扫描不会额外刷怪。每次有约 1 秒落点预警，相邻约 1.2 秒，避开医疗兵、治疗点、补给和实体墙；无安全位置则延后。每房最多两只处于蓄力或扑击，起手至少间隔 0.55 秒。冲流/复苏关闭队列并清除余敌，不要求清完预算。重试不复制同一批敌人，尚活敌人保留伤势并安全重定位。

鼠标决定方向，精准枪与探针射线在首实体停止。喷雾逐目标判断角度、射程和首实体遮挡；前方 Hunter 仍能挡住治疗，不能穿墙或穿过前敌伤害后敌。可治疗结构允许射线进入自身血栓，该例外不允许穿血栓攻击敌人。预览、伤害、治疗和特效共用求交结果；喷雾提供 13 条裁剪射线的真实轮廓。

三个被动采样位置仍为 `(600,900)`、`(1180,730)`、`(780,500)`；唯一故障位于 `(1020,638)`，其前有输入、其后无响应。修复前脉冲停止，修复后真实传播至末端；重复 E 不会清空成果。常驻任务依据房间、病情与库存显示可执行目标，冲流后尚在主血管时先指向心腔入口，折返时也提供返回路线。仅明确已知目标提供边缘提示。

## 输入、恢复与存储

- WASD 移动，Shift 疾行；鼠标瞄准，左键持续治疗或射击。右键精瞄降低移动速度，显示被首个实体截断的射线、命中点与目标类型；不吸附、不自动开火、不额外降低射速。
- Q 开关扫描；E 领取补给、打开可选箱或操作主流阀和房门；R 提前装填。1/2/3 或小键盘选择工具，工具栏可点击。
- Space 在复苏后解锁循环冲刺，按移动方向发动，无移动方向时使用瞄准方向。冲刺自然结束或暂停中止后均需位于可站立位置。
- 共用介质匣 24 发、无限备料、发射间隔 0.2 秒、装填 1.7 秒；最后一发 0.2 秒有效作用结清后自动装填，所有实际发射均耗料。耐久 100；Hunter 生命值 9、普通伤害 1、扫描弱点伤害 3；弱点只在扑击后恢复期暴露，位置固定于此次扑击方向。扑击预警 0.9 秒、伤害 20，伤后短暂无敌。
- 装填 0–0.45 秒为 `eject`，0.45–1.25 秒为 `insert`，1.25–1.7 秒为 `lock`，完成后回 `idle` 并补满 24 发。医疗兵手臂、药匣、背包与工具灯、角色周围进度环及 HUD 条共同反馈，分段播放退匣、插入、就绪音效；可移动，不能开火。
- 余料不超过 6 发提示较低；HUD 显示自动/提前装填与当前分段。按住左键可在装填后续射，松手、暂停、失焦后不续射。重复 R 不重启动作、满匣不装填，输入锁/失败/结束不新启动装填。

入口正常支路附近 `(400,500)` 的医疗箱可选一件：`gel` 缓冲凝胶吸收一次 20 点伤害，检查点重启恢复护层；`steady` 稳流药匣把三段装填同比缩短到 1.2 秒。打开时主机暂停，可关闭后再来；确认即装备且不可重选。无箱路线也能完成全部治疗与战斗。

章节没有超时失败。耐久归零进入失败结算；重启恢复耐久、弹匣和凝胶护层，清空输入与装填，保留完整治疗成果、库存和触发记录，回退未完成治疗。

| 检查点 | 建立时机 | 保留与重试 |
| --- | --- | --- |
| `entry` | 章节开始 | 返回入口，保留已获可选装备和诊断，继续分流。 |
| `bypass` | 任一侧支恢复 | 保留完成侧支、完整血栓局部成果、补给和工具，继续当前病情。 |
| `flow` | 冲流完成 | 从心腔继续；完整故障修复保留，重新执行三拍复测。 |

只有有效游玩推进累计用时、控制器和绘制时间。暂停、帮助、失焦或后台会清空持续输入并冻结心跳、相机、粒子与演出；继续后不会自动续射。失败尝试计入累计用时，重试不清零。退出、重新巡诊和刷新会创建新章节，检查点不跨会话保存。

记录改用 `giant-cure-journey-v2`。首次无 V2 记录时迁移 `giant-cure-journey-v1` 的通关次数，但不继承旧规则最佳用时；V2 已存在则优先采用，不重复合并。旧记录原样保留，不读取 `giant-cure-records-v1`。重复成功不增加病例总数，存储不可用仍可游玩。声音默认关闭。

## 世界、相机与插画

治疗页为 **1280×720**，世界窗口为 `{ x:24, y:84, w:1232, h:552 }`；封面、诊断室、病例档案和结算仍为 **720×1280**。页面切换和窗口缩放同步更新逻辑尺寸、CSS 尺寸及 Canvas 两个 backing 维度，DPR 适配最高为 2。1366×768 下任务与关键扫描结论至少 14 CSS 像素，边缘目标标签完整显示。

入口与主血管的世界尺寸为 1600×1000，心腔为 1800×1200，均超出常态视野。控制器提供世界坐标几何与房间边界，碰撞、交互提示、绘制和测试定位共用这些数据。HUD 使用屏幕坐标，上下边缘显示任务、反馈、扫描、心跳、耐久与工具。

主机维护共享视图：

```js
view = {
  viewport: { x: 24, y: 84, w: 1232, h: 552 },
  camera: { x, y, zoom }, // x / y 为世界中心
  reducedMotion // 主机调用 draw 时传入的布尔值
};
```

世界投影为 `screen = viewport.center + (world - camera.center) * zoom`。指针先从浏览器位置换算为当前逻辑屏幕坐标，再逆变换为世界坐标。相机更新后，每帧重新换算静止指针；窗口缩放后也重新换算。HUD 和世界窗口外的按下不开始治疗，窗口外释放仍会清除持续操作。

普通移动、战斗和治疗使用轻量跟随，默认 `zoom=1.1`，相机限制在世界边界内。房间切换与检查点重试立即定位；短揭示、冲流、复苏和结尾读取控制器的 `cameraCue`，不在普通战斗中抢镜。减少动态效果模式使用静态构图切换与明暗变化。世界粒子使用同一视图变换和裁剪，结算屏幕粒子单独绘制。

运行时仅使用 `assets/heart-journey/` 中 `entry/main/heart` **3 张房间底图**，基础图像来源与提示词保留在 `prompts.json`。共享程序组件绘制封面、接诊与结尾的同一卧躺巨人及树林、村落、呼吸和心跳。七张 `clinic*` 接诊图、`exterior` 外景图、三张 `recovery*` 复苏图以及旧参考母图全部仅作制作历史，不再打包、预载或作为显示回退。

诊断波纹、医疗兵、透明胶囊与导管沿用纸感配色。小医疗兵仍有医疗头盔、面部、白绿制服、背包、独立手臂和靴子；关内上身瞄准与腿部移动分离，持医疗工具。节点、瓣膜、血栓、血流与灯火仍为程序交互，不依赖底图画死的目标。

组织地面自由行走，血管表现为贴地的浅流槽，可跨越；连续曲线和局部粗细变化共用于槽体、血细胞和扫描流向。主血管扩大为两处 170×150 组织岛并加入横向组织肋，心腔中央岛为 220×130，压缩直线路径并提供可绕行掩体。高起组织墙同时阻挡移动与射击，其绘制轮廓、碰撞、敌人导航和射线遮挡共用几何；外围连续组织边缘明确边界。血栓软化时纤维松散、裂缝展开、表层剥离，冲流前仍保持实体轮廓。

采样点附近有灯窗和植物，故障下游没有脉冲通过；修复后脉冲真实经过故障，三次抵达末端才完成复测。复苏镜头覆盖附近变化，结束返回玩家。诊断栏区分未诊断、故障、修复中、复测、稳定与异常再生。

结尾通过共享组件绘制同一卧躺患者，保留 **8 秒**复苏：0–2 秒深呼吸，2–4 秒心区恢复稳定跳动，4–6 秒林梢轻动与村落亮灯，6–8 秒提示心脏稳定与肺部求救。减少动态效果使用稳定构图和轻微明暗变化，不移动镜头或循环摆动。外景隐藏耐久、药剂匣、工具与旧扫描信息，仅保留暂停、声音、叙事字幕和跳过。跳过将剩余模拟时间推进到同一完成态，累计用时包含该段，仍只结算一次。

`window.GiantCureAssets` 暴露 `images`、`ready`、`error`、`clinicError`、`recoveryError` 和 `retry()`；`images` 仅含 `entry/main/heart`，两个装饰插画错误字段兼容保留为 `null`。启动预载三个房间底图；出发在遮罩下等 `ready`，载入失败恢复报告并提供重试或返回。接诊和结尾不需要图片或图片回退。档案直接出诊保持约 250 毫秒淡变。构建内联全部运行时图片、脚本与样式，单文件离线游玩不请求外部资源。

## 主机与控制器接口

控制器注册于 `window.GiantCureGames.heartJourney(api)`：

| 回调 | 约定 |
| --- | --- |
| `progress(value)` | 发布 0–1 的治疗进度。 |
| `setTask(text)` | 发布持续显示的当前问题和目标。 |
| `feedback(text, kind)` | 发布短时操作反馈，不覆盖任务。 |
| `hud(data)` | 发布耐久/护层、弹药、`reloadRemaining/reloadProgress/reloadStage/reloadDuration/reloadAutomatic`、工具、装备、扫描、阶段、房间、检查点与冲刺状态。 |
| `offerEquipment()` | E 打开未领取的可选箱；主机暂停并展示二选一，关闭可稍后返回。 |
| `effect(x, y, color, count)` | 发布世界坐标粒子，由主机统一变换、裁剪和暂停。 |
| `sound(name)` | 默认静音的共享通道，支持心跳、冲流、命中，以及 `reloadOut/reloadIn/reloadReady/empty`。 |
| `success()` / `fail(reason)` | 交给主机结算；控制器防止重复触发。 |

返回接口保留 `update(dt)`、`draw(ctx, activeTime, view)`、`pointerDown/Move/Up/Cancel`、`keyDown(code, repeat)`、`keyUp(code)`、`clearInput()`、`retryFromCheckpoint()`、`getDebugState()`，新增 `chooseEquipment('gel'|'steady')`：仅在箱边且未领取时成功，原子领取后返回 true。主机在暂停的选择面板中调用，确认或稍后再选后恢复。键码使用 `KeyboardEvent.code`，工具键支持 `Digit1..3/Numpad1..3`；指针使用世界坐标，右键为 `button:2`。

控制器只维护一个 `heartbeatClock`。`beat()` 给出 `phase/pulse/safe/state/period`，瓣膜、血流、传导脉冲、城市和灯光读取同一快照。跨拍触发声音，长帧不集中补播历史心跳；复苏首声强心跳由阶段事件触发。脉冲抵达末端才更新下游接收与复测计数，不能用播放完演出替代诊断成功。

绘制模块为 `window.GiantCureJourneyArt.draw(ctx, snapshot, activeTime, view)`，只读快照并负责世界裁剪、变换和绘制，不计算治疗结果。`activeTime` 由主机推进，暂停时不使用仍在流逝的墙上时钟。外景调用 `GiantCureGiantArt.draw(ctx, options)`，其中 `options` 包含 `bounds:{x,y,w,h}`、有效秒 `time`、0–1 的 `restored`、`reducedMotion`、`heartVisible` 与 `recovering`。共享组件的 `draw/getFrame` 返回同一目标画幅内的 `heart:{x,y}` 投影；结尾的呼吸、心跳、树梢与灯光统一读取 `exteriorRecovery.elapsed`。

接诊绘制为 `window.GiantCureClinicArt.draw(ctx, clinic, elapsed, images)`，保留可选 `images` 参数但不依赖图片。只读 `getFrame(clinic, elapsed, images)` 返回相同的 `heart/scanProgress/shot/camera`，`shot` 保持 `arrival/exam/chest` 兼容枚举。`heart` 为 624×570 接诊画面内的逻辑坐标，DOM 定位、导管终点、胶囊落点与入体推进共用这一来源。`drawPreparation(ctx, progress, reducedMotion)` 在过场克隆的同尺寸接诊画布内完成装舱和投送，不再切到独立准备页。

巨人、诊断与投送始终使用同一构图，SVG 只保留共享心区定位。主机在立即跳过后出发时同步绘制报告帧，再将 Canvas 当前像素复制进过场克隆，避免 `cloneNode()` 留下空位图；装舱与投送继续绘制此克隆画布。演出只读取主机累计进度，暂停时人物、诊断波纹与心跳冻结；报告帧保持稳定。缩放时根据同一逻辑画幅重新定位，胶囊到达心区后再开始镜头推进。

`getDebugState()` 返回冻结的深拷贝，含世界尺寸、边界、房间、玩家、工具、节点、门口、碰撞物、瓣膜、路径、敌人、血栓结构、传导、异常组织、心跳和检查点；`cameraCue` 提供 `kind/target/progress`，首次心腔揭示有 `revealRemaining`。测试通过公开输入驱动玩法，不能修改快照跳关。

`toolPreview` 保留 `from/to/kind/hitType/targetId/weakpoint/blocked/label/range`，新增 `tool/angle/targets/fanPoints`；喷雾 `fanPoints` 为 13 条首实体裁剪射线，`targets` 是去重后的实际命中，不由绘制层另算。`shot` 使用相同字段并增加 `age`。`guidance` 保留 `kind/label/text/source/target/waiting`，语义为当前明确的房门、补给或已知病灶，未知目标时为 null。

V2 快照新增 `tool/tools/equipment/shield/reloadDuration/reloadAutomatic`、`branches`、`supplies`、`chest`、`fault`、`scanTargets`、`conductionSignal`。补给状态为 `waiting/transit/ready/collected`；传导提供实际 `pulses`、被动 `samples`、`repaired/verifiedBeats/requiredBeats`。`connection/conduction` 兼容保留空数组，不参与通关判定。工具持有、补给领取与已完成局部成果均在检查点恢复时保留。

`player.velocity/moving/walkDistance` 驱动实际步态；`reloadProgress` 为装填期间 0–1、闲时 0，`reloadStage` 为 `idle/eject/insert/lock`。`encounter` 为当前房间、`encounters` 为房间映射，包含 `room/alive/pending/budget/spawned/cap/closed/triggered`；`spawnTelegraphs` 为当前房间待刷点，含位置、半径、剩余秒数和 0–1 进度。`endingDuration=11.8`，`exteriorRecovery={elapsed,duration:8,progress}` 是独立外景进度快照；均不能通过改写来跳关。

主机 `window.GiantCure.snapshot()` 追加复制后的 `view/logicalSize/reducedMotion/particles/activeTime`。`clinic` 提供 `phase`（`idle/arriving/examining/report/ready`）、累计演出秒数 `elapsed` 和 `paused`，正常完成为 **3 秒**、减少动态效果完成为 **0.48 秒**。`diagnosis.phase` 仍为 `idle/scanning/ready`，显现与检查映射 `scanning`，报告开始映射 `ready` 并关联 `heartJourney`；可出发还要求 `clinic.ready`。`transition.phase` 为 `idle/preparing/departing/waiting/arriving`，准备阶段完成装舱及投送后才进入 `departing`；过场中的病例为 `heartJourney`，结束或取消后为 `null`，完成后才进入 `playing`。快照只读，UI 跳过操作主机流程，不暴露跳关接口。
