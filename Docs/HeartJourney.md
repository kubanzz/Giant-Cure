# 心脏巡诊：二维 V4 章节实现说明

V4 围绕“观察 → 扫描诊断单 → 针对治疗 → 关闭威胁来源 → 主动验证”展开。入口教会单次救治，主血管加入分流与分层治疗，心腔要求双区综合治疗和三次主动复测。首玩 6–8 分钟仍是调优目标，真人体验与趣味性尚待盲测。

## 地图与关卡推进

| 区域 | 世界尺寸 | 目的与推进条件 |
| --- | --- | --- |
| 血管入口 | 2000×1250 | 比较正常与缺血支路；使用 1 清除入口凝块，实际恢复供血才开放瓣膜后通路。 |
| 主血管与侧支 | 2200×1400 | 西侧有掩护但治疗较慢、东侧暴露但较快，任选一侧疏通并领取喷头。使用 2 裂解两处纤维，再用 1 处理核心；稳定度至少 60 时按 E 释放主流。 |
| 心脏内腔 | 2600×1700 | 西区先用 2 裂解纤维、东区先用 1 疏通凝块，之后分别用 3 接通传导。可自行选择先后顺序，每修好一区即停止该区增援并建立检查点。 |
| 同步验证与撤离 | 心腔内 | 双区接通且稳定度至少 60 后，在同步核心用 3 分三次发出验证脉冲；每次须实际抵达下游才计一拍，长按只发一次。三拍通过才打开实体出口；出口 E 进入八秒巨人复苏。 |

扩大世界尺寸同时重排病灶、维护组织、通道、补给和敌人生成位置；工具与扫描有效范围保持不变。血流、脉冲、不同形态病灶和逐区复苏承担主要视觉引导，不用加长照射或强制等候凑难度。

## 扫描、信息与暂停

- Q 开关扫描，锁定一个范围内对象；优先鼠标指向，之后按距离选择。普通半径 145，主血栓 230，读取 1.35 秒；出范围保留该状态的进度，完成后自动关闭扫描。
- 入口缺血检测点与凝块是一张诊断，主血栓及其纤维、核心共享一张分层诊断。维护组织、两区病灶和同步核心也能诊断。
- 首次关键对象或其新状态完成扫描后自动展示诊断单，只有名称、简短结果与治疗指示。相同对象、相同状态的重复扫描仅作短反馈；J 或“诊断单”按钮主动回看最新实际状态。
- 普通画面只保留焦点名称、短失败原因、最近 E 互动及必要进度；装饰和非关键物件无描述。诊断结果不再沿组织铺开，固定扫描栏只显示当前扫描状态。
- 诊断单出现时控制器立即停止剩余切片，主机停止更新；计时、装填、敌人、投射物、组织、心跳、补给、相机、粒子和绘制时间统一冻结。确认清输入后继续；Esc 确认诊断并进入普通暂停，失焦和后台保留报告。
- 扫描不成为治疗已知病灶的额外命中门禁。错误工具、距离、墙与前方敌人的短提示仍读取真实治疗求交结果。

## 工具、防守与检查点

1 精准枪用于凝块、暴露核心、组织修补与冲撞后弱点；2 裂解喷头用于近距纤维和覆盖；3 脉冲探针用于双区传导及同步验证。射程分别为 225 / 145 / 225；喷头夹角 60°。三枪共享 24 发、无限备料和 0.2 秒发射间隔，三段装填从 1.7 秒缩短到 **0.85 秒**，R 提前装填、空匣自动装填。工具补给约三秒沿恢复血流送达，按 E 领取，不自动换枪。探针落在首次诊断心腔区旁的安全位置，避免返回入口领取。

每战斗区两个维护点，各 50 完整度，当前未修复损伤合成心脏稳定度。单次组织命中扣 10；1 每秒修补 20，即使有纤维覆盖也可直接修；2 清覆盖需 0.8 秒有效作用，清理本身不回血。单点归零仍可修，稳定度或医疗兵耐久归零才失败。

凝集体冲撞后暴露弱点；纤维织体投放覆盖物。主血管最多四只，心腔最多四只，同时最多两只攻击；首批两只，之后每八秒尝试补充一只，提前约一秒预警并避开关键对象。心腔敌人与各自病灶、维护组织关联，接通一区后停止该来源并清除其残留威胁；完成治疗比反复清怪更能改变局势。

检查点为入口、任一侧支恢复、主血流恢复，以及心腔任一区传导恢复。失败重试保留完整治疗、已知诊断、工具和补给，清除当前敌人与预警，恢复组织、医疗兵和弹匣，给予三秒准备。未完成治疗回零，已完成心腔区域保留；复测必须重新发出并接收三次真实脉冲。失败用时继续累计，退出或刷新清除本次检查点。

WASD 移动、Shift 疾行、Space 冲刺；左键使用，右键精瞄并预览真实首个命中。Tab 暂停选枪，松开确认；失焦、后台和 Esc 取消候选。同步验证阶段可以移动、扫描和选枪。暂停恢复不继承持续射击或移动输入。

## 接口、评级与存档

控制器新增 `acknowledgeDiagnosis()` 和 `reviewDiagnosis()`。只读快照新增 `scanFocusId`、`pendingDiagnosis`、`diagnosisReport`、`heartSectors`、`syncCore`、`sources`、`runMetrics` 与 `performance`。诊断单包含 `{targetId,title,result,actions,requiredTool,revision}`；状态按病灶治疗层、区域接通及组织健康/损伤/覆盖组合区分，不按每一滴完整度反复弹窗。

主机每次更新后读取 `pendingDiagnosis`，使用 `modalKind='diagnosis-report'`；主机有效时间取控制器实际推进量，不能把报告截断后未执行的时间计入巡诊。`getDebugState()` 保持冻结深拷贝；主机快照结果也复制嵌套评级数据，不能通过快照改写实局。

| 徽章 | 本次达成条件 |
| --- | --- |
| 组织守护 | 全程最低稳定度至少 60 |
| 精准医师 | 命中至少三只不同凝集体的暴露弱点 |
| 稳健巡诊 | 本次没有检查点重试 |

三枚徽章为 S、两枚为 A、零至一枚为 B；通关结算显示本次评级和各徽章。`runMetrics` 记录最低稳定度、已命中弱点的敌人 ID 与重试次数。重试不清除本次最低稳定度或弱点记录。

存档键为 `giant-cure-journey-v4`，保存 `{wins,bestSeconds,bestGrade,medals}`；`medals` 是历史已达成 ID 集合。已有 V4 优先，否则按 V3 → V2 → V1 选择已有记录，仅迁移通关次数，清除旧规则最佳时间和评级；旧记录不改写。新通关分别更新最快时间、最高评级与累计徽章，存储不可用仍可游玩。

## 构建与验收

治疗逻辑画幅保持 1280×720，世界窗口 `{x:24,y:84,w:1232,h:552}`；并行改造后的接诊页同为横版，封面与结算保留竖版病历簿，DPR 最高 2。本轮关卡复用 `entry/main/heart` 三张底图；整合入口另包含接诊页的 `scanGiant` 插画，交互与复苏使用程序绘制，离线单文件无外部请求。

编辑源码后执行 `node scripts/bundle.js`。控制器、防守、组织修复、主机、渲染、标签、基础浏览器、完整路线及诊断浏览器专项分别验证对应行为；测试通过公开输入推进，不写只读快照跳关。诊断专项 `tests/journey-diagnosis-browser.cjs` 验证真实报告、装填与像素冻结、重复扫描、J 回看、失焦、防误输入及 DPR 1/2。

本轮最终实跑数字与入口哈希由 README 的 V4 验证记录注明；较早 V2/V3 数字属于历史版本。真人首玩时长、理解、递进感、成就感、复玩意愿和声音效果仍待同一批五人盲测，不以自动通关替代。至少 4/5 人应能无口头提示完成并解释扫描、三枪、组织损伤、病灶来源和主动三拍；详细模板见 `HeartJourneyPlaytest.md`。
