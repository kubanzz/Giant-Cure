# 心脏巡诊：二维横屏章节实现说明

本章以“诊断 → 分流降压 → 边躲避边治疗 → 血流冲开 → 接通传导 → 生命复苏”构成二维俯视的生态疗愈体验，首玩目标为 **3–5 分钟**。目标时长和体验效果尚待真人验证，不以自动操作时长代替。

本轮保留三个房间、三种基础工具和三个检查点。桌面键鼠是主要平台，心脏城市与纸感插画作为表现方向。肺部只在结尾求救中出现；不扩展其他器官、武器、敌人类型或 UE 系统。本目录的七份原始 3D / UE 规划保留为参考，本文件定义网页二维章节的实现口径。

## 章节与规则

| 状态 | 玩家行为与推进条件 |
| --- | --- |
| `diagnosis` | 对比入口正常支路与异常通路的流量、压力；扫描异常压力后可进入主血管，继续诊断血栓。正常支路扫描可选且可折返。 |
| `bypass` | 两组侧支分别依次连接 A→B；第二组末端要求舒张安全窗口。每恢复一组，血细胞改道，上游压力下降。 |
| `combat` | 首只 Hunter 教学，学习躲避扑击和扫描弱点；击败后开放血栓治疗。 |
| `clot` | 分别扫描、软化三处血栓结构。第一处软化后出现两只干扰者，后续治疗与战斗同时进行。 |
| `burst` | 双侧支恢复且三处结构软化即可启动主流阀，无须清完敌人。约 4 秒冲流带走血栓与剩余 Hunter，建立主血流检查点。 |
| `conduction` | 从窄入口揭示巨大心腔，首次进入约 1.5 秒镜头揭示后恢复操作。扫描传导失序，再依次连接 A→B→C；此段无战斗。 |
| `recovery` | 约 6 秒复苏：短暂安静、第一声强心跳、组织传光、灯火与植物依次恢复，随后解锁冲刺。 |
| `escape` | 循环冲刺越过出口屏障；扫描异常组织，持续治疗约 1.5 秒将其暂时压制。 |
| `ending` / `complete` | 7 秒结尾演出：0–1.8 秒暂时压制，1.8–3.8 秒再生，3.8–7 秒巨人胸口搏动与肺部求救，结束只结算一次。 |

扫描不耗能，也不暂停世界，优先描述症状和状态。普通目标扫描范围为 145 世界单位，血栓总诊断可在 230 单位内读取；扫描约 1.35 秒完成。常驻任务与临时反馈独立，帮助按阶段解释因果。错误连接仅清除当前序列，不扣耐久；第二侧支错过窗口时可保留首端并等待下一次舒张。提前冲流与直接射击血栓不能跳过治疗条件。

瓣膜与第二侧支只读取统一心跳。瓣膜闭合时阻挡通行，重叠时安全推回进入侧，不造成伤害；本轮不加入血流推力。侧支恢复、结构软化、血栓裂解和下游恢复都有独立可见变化。

三处结构分别扫描，每处治疗约 3.2 秒；暂停照射或躲避时保留当前尝试的治疗进度。战斗不锁回程门，可暂退入口，但不补耐久或弹药，敌人伤势与当前波次保留。实体组织阻挡射击，Hunter 的移动与扑击同样遵循碰撞。

## 输入、恢复与存储

- WASD 移动，Shift 疾行；鼠标瞄准，左键持续治疗或射击。右键精瞄降低移动速度并显示辅助射线，不额外降低射速。
- Q 开关扫描，在范围内读取附近症状和弱点；E 接近后交互并连接节点；R 装填。
- Space 在复苏后解锁循环冲刺，按移动方向发动，无移动方向时使用瞄准方向。冲刺自然结束或暂停中止后均需位于可站立位置。
- 弹匣 24 发、无限备弹、装填 1.7 秒；初始耐久 100。Hunter 生命值 6，普通伤害 1，扫描弱点伤害 3；扑击前有预警，每次命中扣 20 耐久，受伤后短暂无敌。

章节没有超时失败。耐久归零进入失败结算，玩家可以重启最近检查点。重启恢复耐久、弹匣并清空输入和装填，保留大型治疗成果，重置当前阶段敌人、未完成连接与局部治疗。

| 检查点 | 建立时机 | 保留与重试 |
| --- | --- | --- |
| `entry` | 章节开始 | 返回入口，重新诊断、分流与治疗。 |
| `bypass` | 双侧支恢复 | 保留诊断和两条侧支，重启当前遭遇与血栓治疗。 |
| `flow` | 冲流完成 | 保留分流和主血流，从心腔重新完成传导与复苏流程。 |

只有有效游玩推进累计用时、控制器和绘制时间。暂停、帮助、失焦或后台会清空持续输入并冻结心跳、相机、粒子与演出；继续后不会自动续射。失败尝试计入累计用时，重试不清零。退出、重新巡诊和刷新会创建新章节，检查点不跨会话保存。

记录继续使用 `giant-cure-journey-v1`，保存通关次数与最佳秒数，兼容已有心脏记录。不读取或迁移 `giant-cure-records-v1`。目录只统计实际可玩的心脏病例，成功一次从 `0 / 1` 变为 `1 / 1`，重复成功不增加病例数量。存储不可用时降级为正常游玩、不保存记录。声音默认关闭。

## 世界、相机与插画

治疗页为 **1280×720**，世界窗口为 `{ x:24, y:84, w:1232, h:552 }`；封面、病例目录、结算仍为 **720×1280**。页面切换和窗口缩放同步更新逻辑尺寸、CSS 尺寸及 Canvas 两个 backing 维度，DPR 适配最高为 2。

入口与主血管的世界尺寸为 1600×1000，心腔为 1800×1200，均超出常态视野。控制器提供世界坐标几何与房间边界，碰撞、交互提示、绘制和测试定位共用这些数据。HUD 使用屏幕坐标，上下边缘显示任务、反馈、扫描、心跳、耐久与工具。

主机维护共享视图：

```js
view = {
  viewport: { x: 24, y: 84, w: 1232, h: 552 },
  camera: { x, y, zoom } // x / y 为世界中心
};
```

世界投影为 `screen = viewport.center + (world - camera.center) * zoom`。指针先从浏览器位置换算为当前逻辑屏幕坐标，再逆变换为世界坐标。相机更新后，每帧重新换算静止指针；窗口缩放后也重新换算。HUD 和世界窗口外的按下不开始治疗，窗口外释放仍会清除持续操作。

普通移动、战斗和治疗使用轻量跟随，默认 `zoom=1.1`，相机限制在世界边界内。房间切换与检查点重试立即定位；短揭示、冲流、复苏和结尾读取控制器的 `cameraCue`，不在普通战斗中抢镜。减少动态效果模式使用静态构图切换与明暗变化。世界粒子使用同一视图变换和裁剪，结算屏幕粒子单独绘制。

三张无字房间底图与一张巨人外景放在 `assets/heart-journey/`，由内置 imagegen 生成。交互角色、节点、瓣膜、血栓、血流、灯火和恢复变化由程序绘制，不依赖底图上画死的交互物。

`window.GiantCureAssets` 暴露 `images`、`ready`、`error` 和 `retry()`；`images` 的键为 `entry/main/heart/exterior`。启动时预载，点击病例卡后等待 `ready` 自动进入，不新增开始按钮；失败提供重试或返回。构建脚本把所有本地图片转为内联 data URL，直接打开单文件时不访问远程资源。

## 主机与控制器接口

控制器注册于 `window.GiantCureGames.heartJourney(api)`：

| 回调 | 约定 |
| --- | --- |
| `progress(value)` | 发布 0–1 的治疗进度。 |
| `setTask(text)` | 发布持续显示的当前问题和目标。 |
| `feedback(text, kind)` | 发布短时操作反馈，不覆盖任务。 |
| `hud(data)` | 发布耐久、弹药、装填、扫描、阶段、房间、检查点、重试与冲刺状态。 |
| `effect(x, y, color, count)` | 发布世界坐标粒子，由主机统一变换、裁剪和暂停。 |
| `sound(name)` | 使用默认静音的共享声音通道，支持普通及强心跳、冲流等事件。 |
| `success()` / `fail(reason)` | 交给主机结算；控制器防止重复触发。 |

返回接口为 `update(dt)`、`draw(ctx, activeTime, view)`、`pointerDown/Move/Up/Cancel`、`keyDown(code, repeat)`、`keyUp(code)`、`clearInput()`、`retryFromCheckpoint()` 和 `getDebugState()`。键码使用 `KeyboardEvent.code`；指针数据为世界坐标，右键为 `button:2`。

控制器只维护一个 `heartbeatClock`。`beat()` 给出 `phase/pulse/safe/state/period`，第二侧支、瓣膜、血流、城市和灯光读取同一快照。跨拍触发声音，长帧不集中补播历史心跳；复苏第一声强心跳由阶段事件触发。

绘制模块为 `window.GiantCureJourneyArt.draw(ctx, snapshot, activeTime, view)`，只读快照并负责世界裁剪、变换和绘制，不计算治疗结果。`activeTime` 由主机推进，暂停时不使用仍在流逝的墙上时钟。

`getDebugState()` 返回冻结的深拷贝，含世界尺寸、边界、房间、玩家、工具、节点、门口、碰撞物、瓣膜、路径、敌人、血栓结构、传导、异常组织、心跳和检查点；`cameraCue` 提供 `kind/target/progress`，首次心腔揭示有 `revealRemaining`。测试通过公开输入驱动玩法，不能修改快照跳关。

主机 `window.GiantCure.snapshot()` 追加复制后的 `view`、`logicalSize`、`reducedMotion`、`particles`、`activeTime`，用于检查显示与暂停。不暴露可改写运行状态的接口。
